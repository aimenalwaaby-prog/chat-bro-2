تقرير حالة مشروع Chat Bro 2
============================
التاريخ: 2026-10-30
المستودع: https://github.com/aimenalwaaby-prog/chat-bro-2
الفرع: main

هذا الملف يجمع بصورة شاملة ما تم تنفيذه في المشروع، وما تم رفعه إلى GitHub، وما تبقى من الأعمال أو يتطلب إعدادات خارجية.

أولًا: حالة المشروع الحالية
---------------------------
المشروع مقسم إلى واجهة ويب مبنية على Expo، وخادم API مستقل، وخدمة وسائط منفصلة، وقاعدة بيانات لحفظ المستخدمين والمحادثات والمفاتيح والمكتبة.

الاستضافة معرفة في render.yaml على Render، وليست على استضافة Manus:

- موقع الويب: https://chatbro-web.onrender.com
- خادم API: https://chatbro-api.onrender.com
- خدمة الوسائط: https://chatbro-media-3.onrender.com
- النشر التلقائي من فرع main مفعّل في تعريف الموقع.

تم التحقق من الموقع وأعاد HTTP 200.
تم التحقق من API وأعاد HTTP 200 من المسار /api/health.

تم نقل الأدوات الإضافية إلى القائمة الجانبية، ومن ضمنها:

2. فصل محادثات النماذج

تم تنفيذ نظام محادثات مستقلة لكل نموذج كما طلب المستخدم:

- عند اختيار نموذج تبدأ جلسة محادثة جديدة.
- عند العودة إلى النموذج لا يتم فتح السجل السابق تلقائيًا.
- زر «محادثة جديدة» ينشئ جلسة جديدة فورًا.
- كل جلسة لها معرف مستقل.
- يتم حفظ النموذج المستخدم مع المحادثة.
- يتم حفظ رسائل المستخدم والمساعد.
- يتم حفظ عنوان المحادثة وتاريخ إنشائها وآخر تحديث لها.
- يمكن فتح المحادثات السابقة من زر «المحفوظة».
- قائمة المحادثات السابقة تُعرض حسب النموذج الحالي حتى لا تختلط سجلات النماذج.
- يمكن إعادة تسمية المحادثة.
- يمكن حذف المحادثة ورسائلها وملفاتها المرتبطة.
- الخادم يتحقق من ملكية المستخدم قبل قراءة أو تعديل أو حذف المحادثة.
- يتم تحديث وقت آخر نشاط للمحادثة.

تمت إضافة إجراءات الخادم التالية للمحادثات:

- conversations.list
- conversations.messages
- conversations.create
- conversations.rename
- conversations.remove

المستخدم غير المسجل يستطيع بدء محادثة جديدة محليًا، ويتم الاحتفاظ بجلسات التخزين المحلي بدل الكتابة فوق جلسة النموذج السابقة. أما الحفظ المركزي والاسترجاع من أي جهاز فيتطلب تسجيل الدخول.

3. تسجيل الدخول والحساب

تمت إضافة قسم حساب واضح داخل صفحة الإعدادات/الحساب.

توجد الحالات التالية:

- مستخدم غير مسجل: يظهر زر تسجيل الدخول.
- مستخدم مسجل: يظهر الاسم والبريد وطبيعة الحساب.
- تسجيل الخروج متاح من الحساب.
- المحادثات السحابية ترتبط بحساب المستخدم.
- يتم استخدام cookie على الويب وBearer token على المنصات الأصلية وفق مسار المصادقة الحالي.

تمت إضافة دعم Google OAuth مباشر اختياري على خادم Render، مع المسارات:

- /api/oauth/google
- /api/oauth/google/callback

المسار المباشر يستخدم state موقّعًا بـ HMAC ومهلة زمنية، ويتبادل رمز Google مع خادم Google، ثم ينشئ أو يحدّث المستخدم ويصدر جلسة Chat Bro.

إذا لم تكن بيانات Google OAuth مهيأة، يبقى مسار OAuth الحالي في المشروع فعالًا بدل إظهار تسجيل دخول وهمي.

4. حفظ الرسائل والبيانات

تم ربط المحادثات السحابية بالحفظ الفعلي في قاعدة البيانات:

- حفظ رد المساعد.
- حفظ النموذج ومزود النموذج.
- منع الوصول إلى محادثة مستخدم آخر.

رابعًا: إعداد Google OAuth المطلوب على Render
---------------------------------------------
لتفعيل Google OAuth المباشر بالكامل، يجب إنشاء OAuth Client في Google Cloud Console وإضافة رابط callback التالي إلى Authorized redirect URIs:

https://chatbro-api.onrender.com/api/oauth/google/callback

ثم وضع القيم التالية في خدمة API على Render:

GOOGLE_CLIENT_ID=معرف Google OAuth
GOOGLE_CLIENT_SECRET=سر Google OAuth
GOOGLE_REDIRECT_URI=https://chatbro-api.onrender.com/api/oauth/google/callback
PUBLIC_WEB_URL=https://chatbro-web.onrender.com

وفي خدمة الموقع static site يجب وضع:

EXPO_PUBLIC_GOOGLE_CLIENT_ID=معرف Google OAuth العام

لا يتم وضع GOOGLE_CLIENT_SECRET في الموقع أو APK أو GitHub.

إذا لم تتم إضافة EXPO_PUBLIC_GOOGLE_CLIENT_ID، سيبقى زر الدخول على مسار OAuth الحالي الموجود في المشروع.

خامسًا: ما تبقى من الأعمال البرمجية
------------------------------------
هذه العناصر ما زالت مدرجة للاستكمال المرحلي لأنها تحتاج تطويرًا واختبارًا أوسع من التعديلات الحالية:

1. الإشعارات

تمت إضافة إشعار إنجاز العمل داخل حساب المحادثة الحالية، لكن لم يتم ربط قناة خارجية مثل البريد أو WhatsApp أو Push Notifications لأن ذلك يتطلب اختيار مزود وقيم اعتماد.

المطلوب لاحقًا:

- تحديد قناة الإشعار المطلوبة.
- إنشاء جدول إشعارات داخل قاعدة البيانات.
- إضافة unread/read وحالة الإشعار.
- إضافة إشعارات داخل صفحة الحساب.
- إضافة مزود بريد أو Push أو WhatsApp عند الحاجة.
- إضافة متغيرات الأسرار إلى Render فقط.

2. قارئ الملفات المتقدم

المطلوب استكمال اختبار قارئ الملفات لكل الصيغ التي يعلن عنها التطبيق، ومنها:

- PDF.
- DOCX.
- XLSX.
- CSV.
- TXT.
- Markdown.
- JSON.
- الصور عند دعم OCR.

المطلوب أيضًا اختبار الملفات الكبيرة، الملفات الفارغة، الملفات التالفة، النص العربي، والامتدادات غير الموثوقة.

3. إدارة الملفات والمرفقات

المطلوب توسيع إدارة المرفقات لتشمل:

- ربط المرفق برسالة محددة.
- عرض اسم الملف وحجمه ونوعه.
- حذف المرفق بأمان.
- التحقق من الحجم والامتداد والمحتوى.
- منع الروابط المكشوفة غير المصرح بها.
- اختبار الملفات مع كل مزود يدعمها.

4. مدير مفاتيح المزودين

الهيكل الحالي موجود والمفاتيح مشفرة على الخادم، لكن المتبقي هو:

- اختبار صلاحية المفتاح عند الإضافة.
- اختبار صلاحية المفتاح يدويًا من الواجهة.
- حالة المفتاح: صالح، منتهي، مرفوض، غير مختبر.
- توزيع الطلبات حسب الأولوية والحصة.
- تدوير المفتاح عند تجاوز الحصة.
- إخفاء المفتاح بالكامل عن العميل والسجلات.

5. خادم توجيه النماذج

المطلوب استكمال طبقة مستقلة لتوجيه النماذج على Render:

- مصادقة server-to-server.
- حدود طلبات لكل مستخدم.
- مهلات واضحة.
- إعادة محاولة محسوبة.
- إيقاف الدائرة عند فشل المزود.
- تسجيل تكلفة واستخدام كل مزود.
- مراقبة زمن الاستجابة والأخطاء.
- اختبارات فشل للمزودات.

6. مستودعات ومكتبة النماذج

المطلوب توسيع طبقة Adapters للمصادر المختلفة، ومنها GitHub وHugging Face وReplicate وغيرها حسب ما تسمح به المواصفات الأصلية.

المطلوب تنفيذ:

- جلب البيانات من المصدر الحقيقي.
- التحقق من الرابط والنوع والحجم.
- إضافة نموذج إلى المكتبة.

7. النماذج المحلية

المسار المحلي موجود، والمتبقي هو توسيع:

المطلوب استكمال التحقق من الروابط، وفحص حالة الموقع، وتحسين التصنيفات والفرز، ومنع عرض الروابط غير المتاحة على أنها تعمل.

سادسًا: القيود والإعدادات التي لا يمكن تنفيذها تلقائيًا
-------------------------------------------------------
لا يمكن وضع أسرار Google أو مفاتيح مزودي الذكاء الاصطناعي داخل المستودع أو الواجهة.

لا يمكن اختيار قناة إشعارات خارجية دون تحديد ما إذا كانت المطلوبة بريدًا إلكترونيًا أو WhatsApp أو Push Notifications.

لا يمكن اعتبار نموذج أو مزود مهيأً لمجرد وجوده في الكتالوج؛ يجب إدخال المفتاح وفحص الصلاحية من Render.

لا يمكن اختبار Android الحقيقي من خلال TypeScript أو بناء الويب فقط؛ يلزم جهاز أو محاكي مناسب.
